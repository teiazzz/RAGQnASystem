### 1. 记忆系统（Memory System）

#### 1.1 三层记忆架构

| 记忆类型 | 存储位置 | 作用 | 生命周期 |
|---------|---------|------|---------|
| **短期记忆** | `messages` 表 | 滑动窗口，最近 5 轮对话 | 会话结束后保留 |
| **长期记忆** | `user_memories` 表 | 用户健康档案（过敏史、慢性病、用药史） | 永久，按需召回 |
| **工作记忆** | `AgentState` | 当前任务状态（意图、实体、工具调用） | 单轮，不持久化 |

#### 1.2 核心特性

✅ **向量检索 + 相关性过滤**
- 普通记忆阈值：0.7（防止无关记忆污染）
- 高优先级记忆（过敏史/慢性病）阈值：0.5（确保不遗漏）

✅ **关键词启发式加成**
- NER 实体命中 `relevance_keywords` 时，相似度 +0.15

✅ **防污染机制**
- 新对话不会被旧对话的无关记忆污染
- 通过余弦相似度 + 阈值过滤实现

✅ **重要性分级**
- 1-10 级，过敏史/慢性病等高危信息设为 8-10

### 2. HITL 人在回路（Human-In-The-Loop）

#### 2.1 五类拦截场景

| 场景 | urgency | 触发条件 | 处理方式 |
|------|---------|---------|---------|
| **高危急症** | emergency | 胸痛、呼吸困难、大出血、意识障碍 | 立即建议拨打 120/急诊 |
| **紧急症状** | urgent | 高热不退、严重腹痛、孕妇出血 | 24h 内就医或人工问诊 |
| **复杂用药** | urgent | 孕产妇、婴幼儿、多药相互作用 | 必须咨询医生/药师 |
| **工具失败** | routine | Agent 连续失败 ≥2 次 | 转人工兜底 |
| **用户要求** | routine | 明确说"转人工""找医生" | 转人工服务 |

#### 2.2 双层拦截机制

✅ **前置拦截**（`chat_service.prepare()` 入口）
- 规则匹配高危关键词
- emergency 级别跳过 RAG/Agent，直接返回急诊建议

✅ **Agent 层拦截**
- `escalate_to_human` 工具
- 记录完整 Agent 执行轨迹到 `hitl_events` 表

#### 2.3 审计与质控

✅ **hitl_events 表**
- 记录所有转人工事件
- 支持人工审核标记（`human_reviewed`）
- 用于分析哪些场景自动处理能力不足

## 🎤 面试讲解脚本（重点背诵）

### 问：你的记忆系统怎么防止污染？

> "我用**向量检索 + 相似度阈值过滤**。每条记忆保存时生成 embedding（用 BGE-M3），新对话时计算 `cosine_similarity(query_embedding, memory_embedding)`，只有 ≥0.7 的才召回。
> 
> 过敏史、慢性病等高危记忆（importance≥8）阈值降到 0.5，确保不遗漏。另外还有关键词启发式：如果 NER 实体命中记忆的 `relevance_keywords`，相似度加成 0.15。
> 
> 这样既防止了无关记忆污染新对话（感冒问题不会被糖尿病记忆干扰），又保证了高优先级信息不漏（青霉素过敏史在问头孢时能召回）。"

### 问：短期、长期、工作记忆分别是什么？

> "**短期记忆**就是消息滑动窗口，保留最近 5 轮对话，存在 `messages` 表，用于多轮 query 改写；
> 
> **长期记忆**是用户健康档案（过敏史、慢性病、用药史），存 `user_memories` 表，按需向量检索召回，带相似度阈值防污染；
> 
> **工作记忆**是当前对话的任务状态（意图、实体、工具调用、plan），在 `AgentState` 里，不持久化，单轮结束就丢弃。"

### 问：医疗场景的 HITL 怎么设计？

> "医疗不能让 Agent 随便下结论，我做了**前置拦截 + Agent 层拦截**两层：
> 
> **前置拦截**在 `chat_service.prepare()` 入口用规则匹配高危关键词（胸痛、呼吸困难、大出血等），emergency 级别直接跳过 RAG/Agent，返回急诊建议；
> 
> **Agent 层**有 `escalate_to_human` 工具，触发时记录 HITL 事件到 `hitl_events` 表审计，供质控分析。
> 
> 分级是 emergency（立即急诊）> urgent（尽快人工）> routine（常规转人工）。所有转人工事件都有完整的 Agent 执行轨迹，能分析哪些场景自动处理不了。"

### 问：LangGraph 怎么支持 HITL？

> "LangGraph 有中断/恢复机制（`.interrupt_before(['human_review'])`），可以暂停在某个节点，等人工审核后调 `.resume()` 继续。
> 
> 但我们当前用的是更简单的**转人工终止**：高危症状触发 `escalate_to_human` 后直接返回急诊建议，不继续 Agent 循环。未来可以改成暂停等人工，审核通过后继续原任务。
> 
> 医疗场景下，高危急症不适合暂停等人工——时间就是生命，应该直接建议急诊；复杂用药、罕见病这种才适合人工介入后继续。"

## 📈 后续优化方向

1. **自动记忆提取**
   - 对话结束后 LLM 总结关键健康事实
   - 自动保存到 `user_memories`

2. **记忆遗忘机制**
   - 低重要性记忆超过 N 天自动删除
   - 避免记忆库膨胀

3. **HITL 审核闭环**
   - 人工审核后标记 `human_reviewed=true`
   - 分析误拦率，优化关键词规则

4. **LLM 二次确认**
   - 规则匹配后再用 LLM 判断一次
   - 减少误拦（如"我看电影时胸痛"≠急症）

5. **多模态记忆**
   - 支持存储化验单、处方单（OCR 提取）

## 💰 成本与性能

### 记忆召回性能

- **向量相似度计算**：Python 纯实现，~0.1ms/条
- **召回延迟**：用户有 100 条记忆时 ~10ms（可接受）
- **优化方向**：用 pgvector 原生向量搜索（需添加 `embedding_vector` 列）

### HITL 拦截性能

- **规则匹配**：纯字符串 `in` 判断，<1ms
- **前置拦截**：emergency 级别跳过 RAG/Agent，节省 2-5s
