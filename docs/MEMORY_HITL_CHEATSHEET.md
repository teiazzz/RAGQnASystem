# 记忆系统 + HITL 面试速查卡 🎯

> **5 分钟快速复习版** | 面试前必看

---

## 💾 记忆系统核心三句话

1. **三层架构**：短期（最近5轮消息窗口）+ 长期（user_memories 表，向量检索）+ 工作（AgentState 任务状态）
2. **防污染**：向量相似度阈值 0.7，高优先级（过敏史/慢性病）降到 0.5，关键词命中 +0.15 加成
3. **使用场景**：新对话自动召回相关健康档案，"糖尿病用药"问题召回糖尿病史，"感冒"问题不被污染

---

## 🚨 HITL 核心三句话

1. **双层拦截**：前置（chat_service 入口规则匹配）+ Agent 层（escalate_to_human 工具）
2. **三级分级**：emergency（立即急诊，跳过 RAG）> urgent（尽快人工）> routine（常规转人工）
3. **审计闭环**：hitl_events 表记录所有转人工事件 + Agent 轨迹，供质控分析

---

## 🎤 必背问答（逐字背）

### Q1: 长期记忆怎么防止污染新对话？

> "我用**向量检索 + 相似度阈值过滤**。每条记忆保存时生成 embedding，新对话时计算余弦相似度，只有 ≥0.7 的才召回。过敏史、慢性病等高危记忆（importance≥8）阈值降到 0.5，确保不遗漏。另外还有关键词启发式：NER 实体命中记忆的 relevance_keywords 时，相似度加成 0.15。这样既防止了无关记忆污染，又保证了高优先级信息不漏。"

### Q2: 短期、长期、工作记忆分别是什么？

> "短期记忆就是消息滑动窗口，保留最近 5 轮，存 messages 表；长期记忆是用户健康档案（过敏史、慢性病），存 user_memories 表，按需向量检索召回；工作记忆是当前对话的任务状态（意图、实体、工具调用），在 AgentState 里，不持久化。"

### Q3: 医疗场景的 HITL 怎么设计？

> "医疗不能让 Agent 随便下结论，我做了**前置拦截 + Agent 层拦截**两层。前置在 chat_service.prepare() 入口用规则匹配高危关键词（胸痛、呼吸困难、大出血等），emergency 级别直接跳过 RAG/Agent，返回急诊建议；Agent 层有 escalate_to_human 工具，触发时记录 HITL 事件。所有转人工事件写入 hitl_events 表审计，供质控分析哪些场景自动处理不了。分级是 emergency（立即急诊）> urgent（尽快人工）> routine（常规转人工）。"

## 📊 关键数字（必记）

| 指标 | 值 | 用途 |
|------|---|------|
| **0.7** | 普通记忆阈值 | 相似度低于此值不召回 |
| **0.5** | 高优先级阈值 | 过敏史/慢性病降低阈值 |
| **0.15** | 关键词加成 | 实体命中时的相似度增益 |
| **5** | 短期窗口 | 保留最近 N 轮对话 |
| **19** | 高危关键词数 | 胸痛、呼吸困难等 emergency 级 |
| **8-10** | 高优先级范围 | importance 分数 |

## 🔥 高频追问 + 标准答案

### 追问1: "为什么阈值选 0.7，不是 0.6 或 0.8？"

> "0.7 是我测试后的经验值。过高（0.8+）会漏掉相关记忆，过低（0.6-）会召回无关内容。实际项目中应该用评测集调优，统计不同阈值下的召回率（Recall）和精确率（Precision），找平衡点。过敏史等高危记忆降到 0.5 是安全优先，宁可多召回也不能漏。"

### 追问2: "为什么不用 pgvector，而用 JSONB 存向量？"

> "JSONB 是兼容性方案。用户记忆数量不大（一般 < 1000 条），Python 算余弦相似度足够快（~10ms）。如果记忆量大或对延迟敏感，可以加 `embedding_vector vector(1024)` 列 + HNSW 索引，用 pgvector 原生搜索。我在 document_chunks 表已经用了 pgvector，记忆系统可以无缝切换。"

### 追问3: "HITL 拦截会不会误拦？"

> "会。纯规则匹配有误拦风险，比如用户说'我看电影时胸痛'不一定是急症。可以优化：规则匹配后再用 LLM 做二次判断，结合上下文。另外 hitl_events 表记录了所有拦截，人工审核后标 human_reviewed=true，统计误拦率，反馈优化关键词规则。医疗场景我倾向'宁可误拦也不能漏拦'，安全优先。"

### 追问4: "记忆会不会越来越多，怎么清理？"

> "会。我设计了 importance 字段和 created_at 时间戳。可以定期清理：低重要性（1-3分）且超过 90 天的记忆自动删除；或者设记忆上限（如每用户最多 500 条），超出后删最老的低优先级记忆。过敏史、慢性病这种高危记忆（8-10 分）永久保留。"

### 追问5: "LangGraph 的中断/恢复机制你用了吗？"

> "当前没用完整的暂停-恢复。我用的是**终止式转人工**：高危症状触发 escalate_to_human 后直接返回急诊建议，不继续循环。LangGraph 的 `.interrupt_before()` 适合复杂用药、罕见病这种需要人工审核再继续的场景，高危急症不应该暂停等人工——时间就是生命。未来可以分场景：emergency 终止、urgent 暂停等人工。"

## ⚡ 秒答公式

**记忆污染** = 向量相似度 + 阈值过滤 + 关键词加成  
**HITL** = 前置拦截（规则）+ Agent 层（工具）+ 审计表（质控）  
**三层记忆** = 短期（窗口）+ 长期（档案）+ 工作（任务）

"我演示下记忆系统：用户历史对话里提到'有糖尿病，吃二甲双胍'，我存到 user_memories 表，importance=8。现在开新对话问'糖尿病人能吃阿司匹林吗'，系统自动向量检索召回这条记忆（相似度 0.82），注入 prompt，LLM 结合用户病史回答。但如果问'感冒吃什么药'，相似度只有 0.35，低于阈值 0.7，不召回，防止污染。
